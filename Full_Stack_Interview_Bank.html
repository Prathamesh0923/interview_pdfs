Architecture diagrams

Interviewers often ask you to draw these on a whiteboard. Practise explaining each arrow.

Signup and email verification

sequenceDiagram
  participant U as User
  participant W as Next.js
  participant A as API (FastAPI)
  participant D as Database
  participant Q as Queue / Email
  U->>W: Submit email + password
  W->>A: POST /auth/signup
  A->>D: Create user (Argon2 hash, verified=false)
  A->>D: Store hash(token), expires 24h
  A->>Q: Send verification link
  A-->>W: 202 "Check your inbox"
  U->>A: GET /verify?token=...
  A->>D: Find hash(token), check expiry
  A->>D: verified=true, delete token
  A-->>U: Redirect to login

Login with access and refresh tokens

sequenceDiagram
  participant B as Browser
  participant A as API
  participant R as Redis / DB
  B->>A: POST /auth/login
  A->>R: Rate limit check
  A->>R: Load user, verify hash, check MFA
  A->>R: Save refresh token (hashed, family id)
  A-->>B: Access token (15 min) + refresh cookie (HttpOnly)
  B->>A: API call with access token
  A-->>B: 200
  B->>A: POST /auth/refresh (cookie)
  A->>R: Rotate: invalidate old, store new
  A-->>B: New access token + new refresh cookie

Forgot and reset password

flowchart LR
  F[Forgot password form] --> R{Rate limit ok?}
  R -- no --> X[429]
  R -- yes --> G[Same reply for every email]
  G --> T[Store hash of random token, 30 min expiry]
  T --> E[Email reset link]
  E --> P[Reset page, no-referrer]
  P --> V{Token valid, unused, not expired?}
  V -- no --> I[Show error and request a new link]
  V -- yes --> S[Save new Argon2 hash]
  S --> K[Delete tokens and revoke all sessions]
  K --> N[Send password changed email]
